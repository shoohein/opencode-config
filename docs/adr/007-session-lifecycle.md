# ADR 007: セッションライフサイクル

## コンテキスト

OpenCode セッションは使い捨て運用を前提とするが、ユーザーが「続きをやって」と指示するだけで部分的なプロジェクト状態が復元される UX を実現するには、セッション間でのコンテキスト継承の仕組みが必要である。

問題点:

- セッション再読は人間にとって認知負荷が高く、要約による再コンテキスト化はトークンを浪費する
- 過去のセッション記録を二重管理すると、OpenCode 本体のセッション状態との不一致が起こる
- すべてのセッションで一律にコンテキスト収集を実行すると、コミットや情報照会のような軽量タスクでコストが割に合わない

## 判断

### 1. Stateless Session Operation

- **決定:** セッション自体は状態を持たない。必要なコンテキストは次のセッション開始時に外部から収集する。
- **補足:** セッションタイトルへの接頭辞（【完了】、【中断】）はいわゆる「回収状態」（回収処理が完了したか否か）を人間向けに表示するラベルであり、セッションの内部状態ではない。
- **理由:** セッション自体を stateless にし、必要な情報だけを次セッション開始時に取りに行くことで、トークン消費と認知負荷を最小化する。
- **代替案:**
  - ライフサイクル状態タグ（【進行中】等）によるセッションフィルタ運用
    - **不採用理由:** セッション再読の認知負荷が高く、再開時の要約でトークンを浪費するうえ、セッション数が増えると管理コストが線形に増加するため
- **トレードオフ:**
  - セッション開始時に必ずコンテキスト収集のコストがかかる
  - 収集した情報は「現在の状態」であって「前回のセッションが何をしていたか」ではない。完全なコンテキスト復元にはタスク管理システムが提供する作業継続情報との組み合わせが必要

### 2. Single Source of Truth は現在の状態

- **決定:** コンテキスト収集の情報ソースは、現在のワーキングツリー、git log、タスクチケットとする。
- **理由:** 現在の状態をソースにすることで情報源間の不整合が原理的に発生しない。
- **代替案:**
  - Manifest ファイル（`.opencode/session-context.json`）方式。セッション終了時に要約を書き出し、次セッション開始時にそれを読み込む
    - **不採用理由:** OpenCode 本体のセッション管理との二重管理・不整合リスクがあり、古い Manifest を読み込んでもトークン浪費となるため
- **トレードオフ:** 「前回のセッションで何をしていたか」を正確に伝えられない。この補完はタスク管理システムが提供する作業継続情報に委ねる。

### 3. コンテキスト収集の判断基準

- **決定:** instruction に設定可能なデフォルト基準を記述し、エージェントがユーザー入力の性質に応じて収集の要不要を判断する。
  - デフォルト: 収集する
  - スキップ条件: 単一ファイルの機械的編集、自己完結的コマンド、純粋な情報照会
  - 強制収集条件: 漠然とした指示、作業継続を示唆（"続き"、"resume" 等）
- **理由:** デフォルト収集 + 明らかに不要なケースのみスキップという戦略は、過小収集リスク（コンテキスト不足）を過剰収集リスク（トークン浪費）より優先する。
- **代替案:**
  - 常に収集する
    - **不採用理由:** コミットや情報照会のような軽量タスクで収集コストがかかりすぎるため
- **代替案:**
  - ユーザーの明示的な opt-in に任せる
    - **不採用理由:** 判断の負担がユーザーに偏り、回収漏れが発生しやすいため
- **トレードオフ:** 判断基準が個人のワークフローに依存する。instruction のオーバーライド機構でプロジェクト/ユーザーごとに調整可能。

## 検討した代替案

- **代替案:**
  - Manifest ファイル + SSoT のハイブリッド: 特定用途（設計議論セッション等）に限り Manifest を併用する
    - **不採用理由:** ケースバイケースの分岐が実装を複雑にし、SSoT 原則との整合性が取れないため

## 結果

### ポジティブ

- セッション管理の基本原則が確立され、後続の詳細設計の基盤となる
- 情報源間の不整合が原理的に発生しない
- 軽量タスクではコンテキスト収集がスキップされ、トークン浪費を抑制する

### ネガティブ

- コンテキスト収集の判断基準を instruction に書くため、プロジェクトのセットアップ時に追加の記述が必要
- 完全なコンテキスト復元にはタスク管理システムが必須
