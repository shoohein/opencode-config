# ADR 010: create-adr スキル強化 — 抽出モデルとセルフレビュー

## コンテキスト

ADR 007-009（セッション管理システム）の作成・レビューを通じて、LLM が生成する ADR に以下の構造的欠陥が発見された:

- 代替案の捏造（議論に一度も登場していない案を補完）
- 実装詳細の混入（CLI コマンド、データ形式などの設計書レベルの記述）
- メタルールの混入（ADR が ADR の書き方自体に言及）

根本原因は、現行の create-adr スキルがテンプレート穴埋めモデルを採用していたことにある。LLM は「ADR は代替案を書くもの」という形式パターンを優先し、中身が存在しなくても補完してしまう。禁止文（"Do not fabricate"）ではこの挙動を抑制できなかった。

## 関連 ADR

- **ADR 000:** ADR 管理システム — create-adr スキルが実装する基盤規約
- **ADR 007-009:** 問題が発見された ADR 群

## 判断

### 1. ADR 生成に抽出モデルを採用する

- **決定:** テンプレートの各セクションを「埋める」のではなく、議論から情報を抽出し、テンプレートをセクションカタログとしてマッピングする。抽出された情報がないセクションは見出しごと出力しない。
- **理由:** 穴埋めモデルでは空の bullet が LLM に補完を誘発する。抽出モデルでは「議論にあることだけを書く」が構造的に強制され、禁止文に依存しない。
- **代替案:** 「Never fabricate」等の禁止文をスキルに追加する。ルールが存在しても LLM への強制力がなく、ADR 007-009 で無視された実績があるため不採用とした。
- **トレードオフ:** ユーザーが議論しなかった情報は ADR に含まれない。これは意図的な制約であり、不足があれば後日ユーザーが追記すればよい。

#### 1.1 ハイブリッド出力

- **決定:** コンテキスト・判断・理由の 3 セクションは ADR の本質的最小単位として常に出力する。それ以外のセクション（代替案、トレードオフ、関連文書等）は抽出結果がある場合のみ出力する。
- **決定（bullet 単位）:** Decision 内の各 bullet は、抽出結果がある場合、またはユーザーが明示的に「なし」と述べた場合のみ出力する。
- **理由:** 「書かれていない」と「検討した結果なし」は異なる情報価値を持つ。明示的な「なし」はトレース可能な情報として記録する価値がある。

### 2. セルフレビューを導入する

- **決定:** ADR 草案をファイル出力する前に、以下の自己検証を実行する:
  - 削除ゲート: Source Trace（議論に基づかない記述の削除）、Abstraction（CLIコマンド・パス・データ形式の削除）、Meta-Rule（ADRの書き方への自己言及の削除）
  - 品質チェック: 構造・明瞭性・完全性・文法の各観点でレビューし、問題を修正する
- **理由:** 生成時の自己検証により、doc-review-cycle に回す前に除去可能な問題を事前に取り除く。削除ゲートでは修正ではなく削除することで二次捏造を防止する。
- **代替案:** post-hoc レビュー（doc-factuality-reviewer、adr-scope-reviewer）のみに依存する。これらのレビュアーは未実装であり、また事実性の不在証明は原理的に不可能であるため、事前防止の層が不可欠と判断し不採用とした。
- **トレードオフ:** セルフレビューの精度は LLM の自己検証能力に依存する。また、品質チェックが reviewer エージェント定義ファイルを読み込む構成は逆依存を生んでいる — エージェント定義の変更が create-adr の動作に意図せず影響する。本来は評価基準を独立したスキルに抽出し、両者から参照する設計が望ましい。現状はファイル不在時に fallback するため破綻しないが、後日修正が推奨される。

### 3. 未確認項目に synthesized マーカーを付与する

- **決定:** 議論から導出されたがユーザーの明示的な同意が確認できない項目は、ADR に含めた上で HTML コメントでマークする。作成後に件数をレポートで通知する。
- **理由:** ユーザーの注意を逐一要求せず（短気の原則）、かつ将来エージェントが当該項目を参照した際に未確認であることを認識できる。ユーザーが確認したい場合は自発的にレビューすればよい。
- **代替案:** 未確認項目を一括でユーザーに確認する。項目が多いと確認疲れを起こし、適当な承認が連打されて実質的な検証にならないため不採用とした。

### 4. 単一エージェント構成を採用する

- **決定:** 議論に参加したエージェントが、抽出・セクションマッピング・セルフレビューまで一貫して担当する。専用の adr-writer エージェントには分割しない。
- **理由:** 2 エージェントに分割しても、抽出エージェントが捏造する可能性は残り、問題の発生点が移動するだけで根本的解決にならない。KISS の原則に従い、単一エージェントで完結させる。
- **代替案:** フロントエージェント（議論参加者）が事実シートを抽出し、adr-writer エージェントがテンプレートへのマッピングとセルフレビューを担当する。複雑性が増す割に捏造防止効果に差がないため不採用とした。

## 結果

### ポジティブ

- 捏造の防止が禁止文ではなくスキルの構造レベルで強制される
- セルフレビューにより、外部レビューに回す前のノイズが減少する
- synthesized マーカーにより、未確認項目の事後検証と将来エージェントへの伝達が可能になる
- 単一エージェント構成によりスキルの複雑性が最小化される

### ネガティブ

- セルフレビューの精度は LLM の自己検証能力に依存し、完全ではない
- セルフレビューが reviewer エージェント定義ファイルを読み込む構成は逆依存である（詳細は判断2のトレードオフ参照）。
- ユーザーが議論しなかった情報は ADR に含まれない（意図的な制約）
