# ADR 014: セッション管理プラグインアーキテクチャ

## コンテキスト

基本設計書はセッション管理システムの実装アーキテクチャを 4 レイヤー（Plugin、Instruction、Skill、Command）に分割している。このうち Plugin レイヤーは「状態変更（タイトル更新、git notes 付与）」を責務とするが、具体的な構成・ツール分割・責務境界は未確定である。

本 ADR は Plugin レイヤーの詳細設計判断を記録する。

## 関連 ADR

- **ADR 007:** セッションライフサイクル — Stateless Session Operation、SSoT（Single Source of Truth）は現状
- **ADR 013:** セッション回収機構の詳細設計 — 本 ADR の回収トリガー実装は ADR 013 の判断に依存する

## 判断

### 1. プラグインの配置と配布方式

- **決定:** TypeScript のローカルスクリプトとして `plugins/session-management.ts` に配置する。npm パッケージとして公開しない。
- **理由:** 本リポジトリは OpenCode の設定集であり、プラグインもその一部として管理するのが自然である。npm パッケージ化すると公開・バージョン管理・インストールの手間が増えるが、単一リポジトリ内での利用にその価値はない。
- **代替案:**
  - `@opencode-ai/plugin` として npm パッケージ化
    - **不採用理由:** 設定リポジトリにおいて npm パッケージは過剰である。他プロジェクトへの配布が必要になった時点で再検討すればよい。
- **トレードオフ:** 他プロジェクトで再利用する場合はコピーまたはパッケージ化が必要になる。

### 2. ツール分割

- **決定:** 以下の 3 ツールに分割する。
  - `session_title(title)`: タイトル本文を設定する。既存の接頭辞を抽出・保存し、`prefix + newTitle` の形で適用する。
  - `session_mark(status)`: 接頭辞（`完了`、`中断`）を更新する。既存の接頭辞を除去し、新しい接頭辞を付与する。本文は保存する。
  - `session_add_note(commit, note)`: 指定されたコミットハッシュに git notes を付与する。
- **理由:** 各ツールが 1 つの操作に徹することで、責務境界が明確になる。`session_title` と `session_mark` の分離により、タイトルだけを更新したい一般的なケースがセッション管理の接頭辞ロジックに依存しない。Unix 哲学の「do one thing well」に従う。
- **代替案:**
  - 単一ツール `session_update_title(title, status?)` に統合
    - **不採用理由:** 接頭辞付与と本文設定の責務が曖昧になる。タイトルだけ更新したい場合でも接頭辞管理ロジックが混入する。
- **トレードオフ:** セッションクローズ時は `session_title` → `session_mark` の 2 回の API 呼び出しが必要になる。ただしクローズは高頻度操作ではないため許容範囲である。

### 3. 責務境界

- **決定:** ツールは OpenCode API 呼び出しまたは shell 実行の薄いラッパー（thin wrapper）に徹する。接頭辞の選択判断（`完了` か `中断` か）、タイトル文案の生成、git notes の内容生成はすべてスキル側の責務とする。
- **理由:** 基本設計書の疎結合原則に従い、判断はスキルに寄せる。プラグインが判断を持ち始めると、UX や運用ポリシーの変更のたびに TypeScript コードの修正が必要になり、拡張性が損なわれる。
- **トレードオフ:** スキル側の指示品質が低い場合、ツールは不正な入力をそのまま通してしまう。現時点ではバリデーションを持たずスキル側の責務とする。必要に応じて後日追加を検討する。

### 4. 接頭辞ルール

- **決定:** 接頭辞は正規表現 `/^【(?:完了|中断|回収)】\s*/` で識別する。常に単一接頭辞とし、重複付与は不可。接頭辞は表示ラベルであり、システムの制御状態ではない。
- **理由:** `【完了】`、`【中断】` はセッションのライフサイクル表示（基本設計書）、`【回収】` は自動起動セッションの視認性ラベル（ADR 013 §7）である。いずれも人間向けの表示であり、制御判断は OpenCode の `time.updated` と `SessionStatus` を SSoT として行う（ADR 007 §2、ADR 013 §3）。
- **代替案:**
  - 接頭辞を制御状態として利用する
    - **不採用理由:** ユーザーが手動で編集可能なフィールドを制御状態にすると、表示層と制御層が結合し、削除・変更に対する耐性が失われる。接頭辞はあくまで視認性のための補助的手段とし、制御判断は OpenCode API の構造化データに基づく。
- **トレードオフ:** 接頭辞が削除されてもシステムは壊れないが、人間が一覧で判別できなくなる。

### 5. 縮退設計

- **決定:** 依存システム（Git、タスク管理システム）が不在の場合、ツールは例外を投げず `{ output: "...", metadata: { skipped: true, reason: "..." } }` を返す。縮退の判断と後続処理のスキップはスキル側の責務とする。
- **理由:** 基本設計書の前提条件表に準拠。ツールは「できない」を報告するだけに留め、システム全体の縮退判断はスキルに委譲することで、各レイヤーの責務が明確になる。
- **トレードオフ:** スキル側が `skipped: true` を適切に処理しないと、縮退が機能しない。スキルの実装品質に依存する。

### 6. イベントフック

- **決定:** 以下のイベントフックを実装する。
  - `session.created`: ユーザーセッション起動を検出し、ADR 013 に基づく回収スイープを実行する。`【回収】` 接頭辞を持つセッションは early return で除外する。
  - `session.updated`: タイトルに `【回収】` 接頭辞を持つセッションの自動更新を捕捉し、接頭辞が失われた場合に再適用する（ADR 013 §7）。
- **理由:** `session.created` による起動時 1 回スイープは、`chat.message` の毎回発火に比べて API 走査回数を最小化し、回収セッションの暴発リスクを回避する（ADR 013 §1）。`session.updated` による再適用は、OpenCode のタイトル自動更新への防御策である。
- **トレードオフ:** `session.updated` の再適用は、OpenCode がタイトルを自動更新しないバージョンでは不要な処理となる（v1.17.9 での発生有無は実装時に検証する）。

## 結果

### ポジティブ

- ツールの責務境界が明確で、各ツールが 1 つの操作に徹する
- プラグインが判断を持たないため、UX 変更がスキル側の修正だけで完結する
- 縮退設計により、依存システムの不在時も安全に動作する
- 接頭辞を表示ラベルに限定したことで、ユーザー操作による破壊への耐性がある

### ネガティブ

- セッションクローズ時に 2 回の API 呼び出し（`session_title` → `session_mark`）が必要
- `session_add_note` はタスク管理システム不在時は常に skip される（ただし仕様の一部として扱う）
- スキル側の指示品質にツールの動作が依存する
