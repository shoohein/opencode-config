# ADR 008: セッション追跡基盤

## コンテキスト

セッション管理システムにおいて、過去のセッションとその判断を辿れるトレーサビリティが必要である。特に将来の開発者が ADR の判断根拠を検証したい場合に、元のセッションの対話ログを参照できること、およびプロジェクトの判断に一貫性があるかを検証できることが求められる。

問題点:

- git のコミットメッセージだけでは「どのセッションでこのコミットが行われたか」が分からない
- セッション ID はローカルの OpenCode 管理下でのみ有効であり、タスクチケットを別のマシンで参照するとガベージになる
- トレーサビリティ情報を記録しない選択は、判断の一貫性が失われたときの保険を失う

## 関連 ADR

- **ADR 007:** セッションライフサイクル -- 本 ADR はセッションの痕跡をどう残すかの判断

## 判断

### 1. git notes によるセッション追跡

- **決定:** セッションのトレーサビリティ情報は `git notes` としてタスク管理リポジトリのコミットに付与する。
  ```bash
  git notes add -m '{"session":"calm-eagle"}' <task-commit-hash>
  ```
- **理由:** `git notes` はデフォルトで `push` 対象外であり、ローカル情報を他マシンに拡散しない。後付け・追記が可能で、セッション回収（ADR 009 参照）時に情報を遡及追加できる。構造化データを自由に格納できる。
- **代替案:**
  - コミットメッセージトレーラー方式: `git interpret-trailers` で `Session-context` をコミットメッセージ末尾に追記する
    - **不採用理由:** コミットメッセージは共有成果物であり、ローカル固有のセッション情報を埋め込むのは他開発者のノイズになるため
- **代替案:**
  - Manifest ファイル方式: `.opencode/session-logs/` にセッション情報を書き出す
    - **不採用理由:** OpenCode 本体のセッション管理との二重管理が発生し、SSoT の不一致リスクがあるため（ADR 007 §2）
- **代替案:**
  - 記録しない: トレーサビリティ情報を一切残さない
    - **不採用理由:** ADR の決定根拠を検証する手段が失われるため
- **トレードオフ:**
  - 未コミットで中断されたセッションにはコミットが存在しないため git notes を付与できない -- 設計上の制約として許容する
  - `git notes` はタスク管理リポジトリ上のコミットに付与する（タスク管理プラグインが自動生成するコミットが対象）。プロジェクトリポジトリのコミットは対象外
  - `git push` 時に `refs/notes/*` を明示的に指定しないとリモートに送信されない

### 2. 未コミットセッションのトレーサビリティ

- **決定:** 未コミットで中断されたセッションのトレーサビリティは対象外とする（設計上の制約）。
- **理由:** コミットが存在しないケースに無理にトレーサビリティを確保しようとすると、システムが複雑化する割に実益が薄い。事実上、未コミット作業はローカルにしか存在しない情報であり、他マシンからの追跡は不可能という割り切りが合理的。
- **代替案:**
  - コミット強制（変更があれば必ず WIP コミットを作成する）
    - **不採用理由:** セッションクローズ/回収時に WIP コミットを作成する設計で部分的に対応するため、完全な代替案として成立しない（照会のみのセッションはコミットが存在しない）

## 結果

### ポジティブ

- トレーサビリティ情報がコミットメッセージを汚染しない
- 回収処理で後から情報を追記可能
- ローカル情報がリモートに漏洩しない（デフォルト）

### ネガティブ

- 未コミットセッションのトレーサビリティは諦める
- `git notes` の存在を知らない開発者は気づかない。明示的に `git notes show` を実行する必要がある
- タスク管理リポジトリがないと仕組みが機能しない
