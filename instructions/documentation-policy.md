# Documentation Policy

Place documentation under `docs/`.

- `docs/guide/`: user-facing usage guides
- `docs/development/`: developer guides (setup, testing, release, contribution)
- `docs/design/`: describes how the system currently works
- `docs/adr/`: explains why important technical decisions were made

When the subject is the current state of the system, update `docs/design/`. When the subject is a decision — especially one with meaningful alternatives or trade-offs — create or update an ADR in `docs/adr/`.
